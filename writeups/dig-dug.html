DNS Enumeration Challenge

A misconfigured DNS server that answers a basic A-record lookup with the flag itself.

TryHackMe · DNS / Enumeration

Objective

Enumerate a misconfigured/custom DNS server at 10.65.185.133 to retrieve a flag associated with the domain givemetheflag.com.

Recon

An nmap scan of the target showed only one open port:

22/tcp   open  ssh

No port 53 was flagged by default nmap service detection in a way that gave anything away — the box doesn't advertise itself as a DNS server through standard scanning, and SSH was a red herring / not the intended path.

Enumeration

Since the task hinted the server only responds to specific DNS queries for givemetheflag.com, the natural tool is dig, pointed directly at the target as the resolver:

dig @10.65.185.133 givemetheflag.com

Breaking that command down: - @10.65.185.133 — tells dig to query this IP directly as the DNS server, rather than using the system's default resolver - givemetheflag.com — the domain being queried - (no record type specified) — defaults to an A record lookup

Result

The very first query returned the flag directly in the ANSWER SECTION of the response — no need for zone transfers or record-type enumeration. The server had been configured so its "answer" to a basic A-record query for that domain literally was the flag data.

Flag:

flag{0767ccd06e79853318f25aeb08ff83e2}

Takeaway

This challenge illustrates a very simple point about DNS: DNS responses aren't just IP addresses — a DNS server can be configured to return arbitrary data in a record's answer field. Basic enumeration with dig is often the fastest path to spot a misconfigured or intentionally "creative" DNS server, and you don't always need advanced techniques (AXFR, brute-forcing subdomains, etc.) — sometimes the simplest query is the answer.

Command Used

dig @10.65.185.133 givemetheflag.com
